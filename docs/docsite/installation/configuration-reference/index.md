This page lists the variables the Ascender installer reads. Platform-specific and component-specific variables are summarized here and described in full on their own pages.

## How the configuration is read

The installer reads variables from these sources, highest priority first:

1. `custom.config.yml` in the repository root, if it exists. Otherwise `default.config.yml`. Only one of the two files is read.
2. The installer's internal defaults in `playbooks/group_vars/all.yml`.
3. Defaults inside individual roles, such as the external database settings for Ledger.

`config_vars.sh` writes `custom.config.yml` as a complete copy of `default.config.yml` with your answers applied, so a file generated by the script contains every setting. If you write `custom.config.yml` by hand, anything you leave out comes from the internal defaults, which differ from `default.config.yml` in a few places: they do not define `PROXY_TLS_CRT_PATH` or `PROXY_TLS_KEY_PATH`, `k8s_platform` defaults to `k3s`, and `EKS_K8S_VERSION` defaults to `1.33`.

Settings written as nested blocks (`LEDGER_REGISTRY` and `PROXY_CONFIG`) are replaced as a whole, not merged, so include every key you need when you define one.

The defaults in the tables are the values in `default.config.yml`, or the internal defaults for variables that file does not contain.

## Kubernetes platform

| Variable | Default | Description |
| --- | --- | --- |
| `k8s_platform` | `eks` | Target platform: `k3s`, `rke2`, `eks`, `gke`, `aks`, `dkp`, `ocp`, or `tkgi` |
| `k8s_lb_protocol` | `http` | `http` or `https`. With `https`, provide certificates (see [TLS and certificates](#tls-and-certificates)). EKS always serves HTTPS |
| `kube_install` | `false` | K3s: install a single-node K3s cluster on `ascender_host` if K3s is not already installed there. The kubeconfig is then always copied to the control machine |
| `download_kubeconfig` | `false` | Copy or generate the cluster kubeconfig into `~/.kube/config` on the control machine. On K3s and RKE2 it is copied from `ascender_host`; on EKS, GKE, and AKS it is generated with the cloud CLI |
| `kubeapi_server_ip` | `127.0.0.1` | RKE2: routable address of the Kubernetes API, such as the node IP or VIP. Replaces `127.0.0.1` in a kubeconfig copied from a remote node, and is the address used for `/etc/hosts` entries |
| `k3s_master_node_ip` | `127.0.0.1` | K3s: routable address of the K3s node. Replaces `127.0.0.1` in a kubeconfig copied from a remote node, and is the address used for `/etc/hosts` entries |
| `k3s_service_type` | `ClusterIP` | K3s: `ClusterIP` exposes Ascender and Ledger through ingress. `NodePort` exposes Ascender on node port 30080, the Ledger web interface on 30081, and the Ledger parser on 30500 instead. Not in `default.config.yml` |
| `firewalld_disable` | `true` | K3s: stop and disable firewalld on `ascender_host` if it is installed. When `false`, the installer instead opens the ports in `k3s_firewalld_ports` (`6443/tcp`, `80/tcp`, `443/tcp`) and adds the networks in `k3s_firewalld_trusted_sources` (`10.42.0.0/16`, `10.43.0.0/16`) to the `trusted` zone if firewalld is running. Enterprise Linux only. Not in `default.config.yml` |
| `use_etc_hosts` | `true` | Add `/etc/hosts` entries for the host names on the control machine. Applies on K3s, RKE2, DKP, and TKGI; see each platform guide for the address they point at |
| `tmp_dir` | `ascender_install_artifacts/` in the repository root | Directory for generated manifests, backups, and other artifacts |
| `add_kubernetes_repo` | `true` | Add the upstream Kubernetes package repository on the control machine to install `kubectl`. Set it to `false` when `kubectl` comes from a local mirror you have configured |

Platform-specific variables are described in each guide: [EKS](../eks#eks-variables), [GKE](../gke#gke-variables), [AKS](../aks#aks-variables), and [DKP, OCP, and TKGI](../other-platforms). `RKE2_BINARY_URL` and `DKP_CLUSTER_NAME` appear in `default.config.yml` but are not used.

## Offline installation and internal registries

| Variable | Default | Description |
| --- | --- | --- |
| `k8s_offline` | `false` | Use the offline bundle in `offline/` instead of internet resources. See [Offline installation](../offline) |
| `k8s_container_registry` | Empty | Registry and namespace that holds the Ascender images, for example `registry.internal.example.com/ascender`. When set, Ascender, the operator, PostgreSQL, Valkey, the execution environment, and Ledger are pulled from it |
| `k8s_image_pull_secret` | `None` | Name of an existing secret in the Ascender namespace with credentials for that registry. Leave as `None` when none is needed |
| `k8s_ee_pull_credentials_secret` | `None` | Name of an existing secret with credentials for the registry that holds execution environment images. Leave as `None` when none is needed |

## Ledger registry credentials

| Variable | Default | Description |
| --- | --- | --- |
| `LEDGER_REGISTRY.BASE` | Unset | Registry that holds the Ledger images, when it requires a login |
| `LEDGER_REGISTRY.USERNAME` | Unset | User name for that registry |
| `LEDGER_REGISTRY.PASSWORD` | Unset | Password for that registry |

The block is commented out in `default.config.yml`. When you set it, set all three fields. The installer creates a pull secret named `ledger-registry-secret` from these credentials in the Ledger namespace, and the offline bundle playbook logs in to the registry before it pulls the Ledger images.

## TLS and certificates

| Variable | Default | Description |
| --- | --- | --- |
| `tls_crt_path` | `~/ascender.crt` | PEM certificate on the control machine, used for Ascender and Ledger when `k8s_lb_protocol` is `https`. Not used on EKS |
| `tls_key_path` | `~/ascender.key` | Unencrypted PEM private key for `tls_crt_path` |
| `PROXY_TLS_CRT_PATH` | `~/ascender.crt` | Certificate for Galaxy Proxy. `config_vars.sh` sets it to `tls_crt_path` |
| `PROXY_TLS_KEY_PATH` | `~/ascender.key` | Private key for Galaxy Proxy. `config_vars.sh` sets it to `tls_key_path` |
| `custom_cacert_bundle` | Unset | CA bundle that Ascender trusts for outbound TLS connections. Include the system CAs as well as your own, for example `cat /etc/ssl/certs/ca-bundle.crt ~/myca.crt > ~/my-ca-bundle.crt` |
| `custom_ldap_cacert` | Unset | CA certificate that Ascender trusts for LDAP connections |

Paths can start with `~` or use `{{ playbook_dir }}/..` to refer to the repository root.

## Ascender

| Variable | Default | Description |
| --- | --- | --- |
| `ASCENDER_HOSTNAME` | `ascender.example.com` | Host name of Ascender. Required |
| `ASCENDER_DOMAIN` | `example.com` | DNS domain that contains the host names. Required on EKS, GKE, and AKS, where it selects the DNS zone |
| `ASCENDER_NAMESPACE` | `ascender` | Kubernetes namespace for Ascender and Galaxy Proxy |
| `ASCENDER_ADMIN_USER` | `admin` | Ascender administrator user name |
| `ASCENDER_ADMIN_PASSWORD` | `myadminpassword` | Ascender administrator password. Cannot contain double quotes |
| `ASCENDER_IMAGE` | `ghcr.io/ctrliq/ascender` | Ascender image repository. Ignored when `k8s_container_registry` is set |
| `ASCENDER_VERSION` | `25.6.3` | Ascender version, used as the tag of the Ascender and execution environment images. See [Ascender releases](https://github.com/ctrliq/ascender/releases) |
| `ASCENDER_OPERATOR_VERSION` | `25.6.3` | Ascender Operator version. Commented out in `default.config.yml`; `config_vars.sh` asks for it, and otherwise the installer's internal default applies. See [operator releases](https://github.com/ctrliq/ascender-operator/releases) |
| `ASCENDER_MESH_HOSTNAME` | Unset | Host name of the Automation Mesh ingress. See [Automation Mesh](../automation-mesh) |
| `ascender_replicas` | `1` | Number of Ascender web and task pods |
| `ascender_image_pull_policy` | `Always` | Image pull policy: `Always`, `IfNotPresent`, or `Never`. Also used for the Ledger and Galaxy Proxy containers |
| `ascender_garbage_collect_secrets` | `true` | When `true`, the operator deletes the Ascender secrets (including the secret key that encrypts credentials) if the Ascender deployment is deleted. Set to `false` to keep them |
| `ascender_setup_playbooks` | `true` | After installation, add example projects, an inventory, job templates, and a workflow template to Ascender. Skipped on offline installations |
| `ee_images` | One entry for `ghcr.io/ctrliq/ascender-ee:<ASCENDER_VERSION>` | Execution environments to register in Ascender. See [Execution environments](#execution-environments) |

### Execution environments

To register more execution environments at installation time, define `ee_images` as a list of names and images. The list replaces the installer's default, so include the default execution environment if you want to keep it:

```yaml
ee_images:
  - name: Ascender-EE (25.6.3)
    image: ghcr.io/ctrliq/ascender-ee:25.6.3
  - name: my-custom-ee
    image: registry.example.com/automation/my-custom-ee:1.0
```

`config_vars.sh` asks for these entries when you answer `true` to the question about additional execution environments. For managing execution environments after installation, see [Execution environments](/user-guide/execution-environments).

### External PostgreSQL

By default the Ascender Operator deploys PostgreSQL in the Ascender namespace. To use an existing PostgreSQL server, set all of the following. The database must already exist.

| Variable | Default | Description |
| --- | --- | --- |
| `ASCENDER_PGSQL_HOST` | Unset | Host name or IP address of the server, reachable from the Ascender pods. Setting it switches Ascender to the external database |
| `ASCENDER_PGSQL_PORT` | `5432` | Server port |
| `ASCENDER_PGSQL_USER` | `ascender` | Database user |
| `ASCENDER_PGSQL_PWD` | Unset | Database password. Do not use special characters |
| `ASCENDER_PGSQL_DB` | `ascenderdb` | Database name |

The connection uses `sslmode: prefer`. The installer's [backup and restore](/admin-guide/backup) do not support external databases.

### Built-in PostgreSQL storage

| Variable | Default | Description |
| --- | --- | --- |
| `POSTGRES_PVC_SIZE_GB` | Unset (8 GiB, the operator default) | Size of the PostgreSQL volume, in GB |
| `POSTGRES_STORAGE_CLASS` | Unset (cluster default) | StorageClass of the PostgreSQL volume |

<Hint type="warning">

Set `POSTGRES_PVC_SIZE_GB` and `POSTGRES_STORAGE_CLASS` only on new installations. The Ascender Operator does not resize an existing volume or move it to another storage class.

</Hint>
